# Theme and Branding

## Overview

A project's look — its colors, corners, font and logos — lives in its own frontend layer, above the DMS, as plain files: a stylesheet of CSS variables, the `ui.colors` and `branding.logo` keys of its `app/app.config.ts`, and logo files under `public/`. That is the path the DMS theming guide describes, and the files stay hand-editable and versioned with the rest of the project.

`GetTheme` reads those files back, `SetTheme` writes them in one transaction, and `CreateThemeLayer` gives a project without a layer of its own the one a theme is written to. Like every other operation, they edit code, in development: nothing is stored in a database, and a theme reaches production with the next build.

```typescript
import {
  CreateThemeLayer,
  GetTheme,
  SetTheme,
} from "@antelopejs/interface-dms-builder";
```

## Where the Theme Lives

The layer is the highest-priority frontend module the project registers from inside its root — the DMS and installed modules never are — unless the module config names one (`theme.layer`, relative to `projectRoot`). Inside it:

| File | Holds |
| --- | --- |
| `app/assets/css/theme.css` | The variables, unlayered: `:root` for those both modes share, `:root:not(.dark)` for light, `.dark` for dark |
| `app/app.config.ts` | `ui.colors.<role>` — a palette per Nuxt UI color role — and `branding.logo.<slot>.<light\|dark>` |
| `public/branding/` | The uploaded logos, named after their content |
| `dms.frontend.ts` | The layer's entry, which imports the stylesheet |

The light rule is not plain `:root`: unlayered, a `:root` rule also matches the page in dark mode and beats the DMS's own dark values, which live in its `dms` cascade layer. A value set for light alone would show in dark too.

The DMS frontend loader applies a layer's `app/app.config.ts` on its own (`@antelopejs/dms-frontend` 0.5.7 and later), so the entry only imports the stylesheet.

## Read the Theme

```typescript
const result = await GetTheme();
if (!result.ok) {
  if (result.error.code === "not_found") {
    console.log(`no layer yet; CreateThemeLayer would create ${result.error.ref}`);
  }
  return;
}
const { variables, colors, logos, version } = result.data;
```

`ThemeStructure` is the theme as the files hold it:

| Field | Type | Description |
| --- | --- | --- |
| `layer` | `ThemeLayer` | The layer's name and absolute source path. |
| `variables` | `ThemeVariableSets` | `shared`, `light` and `dark`: the custom properties each sets, by name. |
| `colors` | `ThemeColors` | The palette each role takes: `primary`, `success`, `warning`, `error`, `info`. |
| `logos` | `ThemeLogos` | The public path of each slot's file, per mode: `default`, `collapsed`, `email`, `favicon`. |
| `files` | `ThemeFiles` | The files above, relative to the layer. |
| `stylesheetImported` | `boolean` | Whether the entry imports the stylesheet already. |
| `version` | `string` | A content hash of the stylesheet, the app config and the entry, for `expectedVersion`. |

Only what the builder can read back is reported: a palette or a logo path written as a string literal. A value the file computes is the author's, and reads as no override. A stylesheet holding anything but rules of custom properties under those three selectors is reported `unsupported` rather than flattened.

## Write the Theme

`SetTheme` takes the whole theme, as it should be: what the draft leaves out goes back to the DMS default.

```typescript
const theme = await GetTheme();
if (!theme.ok) return;

const result = await SetTheme(
  {
    variables: {
      shared: { "--ui-radius": "0.5rem" },
      light: { "--ui-bg-muted": "#f6f5f2" },
      dark: { "--ui-bg-muted": "#0c0b09" },
    },
    colors: { primary: "violet" },
    logos: theme.data.logos,
    uploads: [
      {
        slot: "default",
        mode: "light",
        contentType: "image/svg+xml",
        data: Buffer.from(svg).toString("base64"),
      },
    ],
  },
  { expectedVersion: theme.data.version },
);
```

- **Uploads** — an upload sets its slot and mode, over whatever `logos` says there. SVG, PNG, WebP or ICO, up to 512 KiB, its bytes checked against its type. The file is named `<slot>-<mode>-<hash>.<ext>`, so a new logo is a new URL no cache keeps serving under the old one; one file sent for several slots is written once.
- **SVG** — written sanitized: scripts, event handlers, `javascript:` links, embedded documents and references to other files are taken out. The result carries an `svg_sanitized` warning when anything was. Mail clients do not show SVG: give the `email` slot a PNG.
- **Old logos** — a file the builder wrote and the theme no longer points at is deleted. A file it did not name is never touched.
- **Values** — a variable's name must be a custom property, its value must not be able to end its declaration (`;`, braces, comments, `url()`, `@import`, `!important`), and a palette name must be one (`violet`, or `brand` for a project's own `--color-brand-50…950`).
- **The entry** — the first save that writes a stylesheet adds its import to the entry. In development that one change reloads the page; the stylesheet, the app config and new logos are applied without one.

Every file is checked before any is written, and a write that fails half way puts back those already written. `stale` comes back when the files changed since `expectedVersion` was read.

## Create the Layer

A project without a frontend layer of its own answers `GetTheme` with `not_found`, its `ref` naming where the layer would go. `CreateThemeLayer` creates it there — `frontend-vue/` beside the sources, with a `package.json` and an entry importing the stylesheet — and registers it from the project's exported `start()`, above the DMS:

```typescript
await AddFrontendModule({
  name: "shop-frontend",
  sourcePath: path.join(__dirname, "../frontend-vue"),
  renderer: { name: "vue", version: "3" },
  priority: 1,
});
```

`start()` is created, or made async, as it needs to be, and the edit is typechecked like any other. A project that has a layer keeps it, and nothing is written. The backend reloads with the registration; the frontend dev server reads its modules at startup, so it serves the layer once restarted.
