# Theme

The **Theme** workspace edits the look of the whole project, beside the page it paints: the page and the DMS around it show every change as you make it. There is one theme for the project, whichever page the editor is open on.

## Simple and Developer

The simple mode offers the accent among the palettes, the backgrounds in light and in dark, a choice of corners, a font, and one logo per mode that goes everywhere a logo shows — the email gets it as a PNG — with an optional square icon for the folded sidebar and the browser tab.

The developer mode lists every token with its light and dark value, any other CSS variable, the status colors, and each logo slot on its own.

## Colors

Each color set per mode is a row showing its light and its dark value side by side. Opening it edits the mode the page shows, with a picker, the DMS's own colors of the same group, and **Back to the DMS default**; the color's code is there behind **#**, or on its own when the value cannot be used. One row is open at a time.

## Font

The font row lists the DMS's own, Geist, and ten fonts under the SIL Open Font License: Inter, IBM Plex Sans, Public Sans, DM Sans, Manrope, Plus Jakarta Sans, Figtree, Atkinson Hyperlegible Next, Nunito and Source Serif 4. Each name shows in its own letters, and a sample above the list takes the font under the pointer. The page shows the one picked at once.

**Save** downloads the font's files into the project, under `public/branding/fonts/`, and declares them in the theme's stylesheet: the dashboard then serves its font itself and fetches nothing from elsewhere, the same on every device. Until then, the editor reads the files from jsDelivr, so picking a font, and saving it the first time, needs the network. A font stack of your own still goes in the code field.

## Light and dark

The **Light / Dark** switch shows the page in either mode without touching your own preference. The builder's frame keeps the DMS look whatever the theme does, in the mode the page shows, so a draft with unreadable colors never makes the editor unreadable.

## Saving

The theme has its own undo history, apart from the page's. **Save** writes it with the page (`SetTheme`).

The theme is plain files of the project's frontend layer, which `@antelopejs/dms-frontend` 0.6 applies on its own: a stylesheet of CSS variables, `ui.colors` and `branding.logo` in its `app/app.config.ts` (`defineDmsAppConfig`), and its logos and fonts under `public/`. The email and favicon slots, like the DMS defaults the editor previews a reset with (`branding.defaults`), come with `@antelopejs/dms` 0.9.

A project without a frontend layer of its own is offered one (`CreateThemeLayer`): `frontend-vue/` beside its sources, registered from its `start()`. Restart the frontend dev server so it serves the new layer.

See [Theme and Branding](https://github.com/AntelopeJS/dms-builder/blob/main/packages/interface-dms-builder/docs/11.theme-and-branding.md) for the files and the rules a save follows.
