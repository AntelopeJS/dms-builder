# Theme

The **Theme** workspace edits the look of the whole project, beside the page it paints: the page and the DMS around it show every change as you make it. There is one theme for the project, whichever page the editor is open on.

## Simple and Developer

The simple mode offers the accent among the palettes, the backgrounds in light and in dark, a choice of corners and of font, and one logo per mode that goes everywhere a logo shows — the email gets it as a PNG — with an optional square icon for the folded sidebar and the browser tab.

The developer mode lists every token with its light and dark value, any other CSS variable, the status colors, and each logo slot on its own.

## Light and dark

The **Light / Dark** switch shows the page in either mode without touching your own preference. The builder's frame keeps the DMS look whatever the theme does, so a draft with unreadable colors never makes the editor unreadable.

## Saving

The theme has its own undo history, apart from the page's. **Save** writes it with the page (`SetTheme`).

The theme is plain files of the project's frontend layer, which `@antelopejs/dms-frontend` 0.6 applies on its own: a stylesheet of CSS variables, `ui.colors` and `branding.logo` in its `app/app.config.ts` (`defineDmsAppConfig`), and its logos under `public/`. The email and favicon slots, like the DMS defaults the editor previews a reset with (`branding.defaults`), come with `@antelopejs/dms` 0.9.

A project without a frontend layer of its own is offered one (`CreateThemeLayer`): `frontend-vue/` beside its sources, registered from its `start()`. Restart the frontend dev server so it serves the new layer.

See [Theme and Branding](https://github.com/AntelopeJS/dms-builder/blob/main/packages/interface-dms-builder/docs/11.theme-and-branding.md) for the files and the rules a save follows.
