The options live in the `config` block of the builder's entry in `antelope.config.ts`. `ajs project modules add @antelopejs/dms-builder` writes that entry under the key `"@antelopejs/dms-builder"`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `projectRoot` | `string` | the process working directory | The app's source root, where page files live. A relative path resolves against the process working directory. Every page, table and query the builder writes lands under it. |
| `api.enabled` | `boolean` | the project's development mode | Forces the builder on or off. |

::note
The module does not read a `factoring` option. Remove it if an older configuration still holds one.
::

## When the builder is on

When `api.enabled` is unset, the builder follows the core's development flag (`GetRuntimeInfo().dev`). The DMS reads the same flag for dev reload. The builder does not read `NODE_ENV`.

| Command | Builder |
| --- | --- |
| `ajs project dev`, `ajs project dev -w` | On |
| `ajs project start`, which starts the project from its build | Off. The process mounts no `/api/builder` routes, so they answer `404`. It registers no frontend module, and the page header shows no builder button. |

`api.enabled: true` mounts the builder on a started build. `api.enabled: false` keeps it off in development.

::warning
With `api.enabled: true` on a deployment, tenant owners can rewrite the deployed sources.
::
