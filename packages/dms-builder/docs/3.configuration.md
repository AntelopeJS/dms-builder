# Configuration

Set options in the `config` block of the `dms-builder` entry of `antelope.config.ts`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `projectRoot` | `string` | the process working directory | Absolute path to the app's source root, where page files live. Every page, table and query the builder writes lands under it. |
| `api.enabled` | `boolean` | the project's development mode | Forces the builder on or off. |

::note
Version 0.3 dropped the `factoring` option; remove it from an older configuration.
::

## When the builder is on

Unset, `api.enabled` follows the core's development flag (`GetRuntimeInfo().dev`), the same flag the DMS uses for dev reload, not `NODE_ENV`:

| Command | Builder |
| --- | --- |
| `ajs project run`, `ajs project run -w` | On |
| `ajs project start` (runs a build) | Off: no `/api/builder` routes (they answer `404`), no frontend module, no **Edit this page** |

Set `api.enabled: true` to mount the builder on a started build on purpose, or `false` to keep it off in development.

::warning
With `api.enabled: true` on a deployment, tenant owners can rewrite the deployed sources. Keep it for environments where that is the intent.
::
